# Windows 自動更新の実機試験

`test-auto-updates` は、レビュー済みの `add-auto-updates` (`c2062d7`) から派生した試験専用ブランチです。アプリの更新処理は共通で、識別情報・保存先・配信先とビルド手順を試験用に変更しています。試験用の設定一式は本体ブランチへマージせず、必要な不具合修正だけを戻します。

## 試験版の識別と保存先

| 項目               | 試験版                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------ |
| アプリ名           | `NicoLiveRecorderUpdateTest`                                                                                 |
| アプリID           | `com.honishi.nico-live-recorder.update-test`                                                                 |
| 設定・履歴・ログ   | `%APPDATA%\nico-live-recorder-update-test`                                                                   |
| 更新キャッシュ     | `%LOCALAPPDATA%\nico-live-recorder-update-test-updater`                                                      |
| 録画の既定保存先   | Windowsの「ビデオ」内の `NicoLiveRecorderUpdateTest`                                                         |
| 更新配信先         | [honishi/nico-live-recorder-update-test](https://github.com/honishi/nico-live-recorder-update-test/releases) |
| 試験するバージョン | 0.5.0 → 0.5.1                                                                                                |

旧版・新版で上記の識別情報は同じです。`NLR_USER_DATA` / `NLR_OUTPUT_DIR` の指定なしでも本番の保存先と分かれ、インストーラーによる再起動後も試験用の設定を使います。設定画面から本番の録画保存先へ変更しないでください。

Windows 11 ARMのVMではx64アプリのエミュレーションを使います。NSISの更新処理を試せますが、Intel/AMDのWindows実機を網羅した確認にはなりません。今回はmacOS版をビルドしません。

## ビルドと配信

本体リポジトリの既存の `release.yml` を、このブランチを指定して手動実行します。

```sh
gh workflow run release.yml --ref test-auto-updates --repo honishi/nico-live-recorder
```

Windowsランナー上でチェックとFFmpegビルドを行い、同じコード・同じFFmpegから2バージョンを作ります。版の変更はランナー内だけで行い、Gitのタグやバージョン変更コミットは作りません。各版のNSISを展開し、FFmpeg、更新情報のSHA-512・サイズ、配信先・キャッシュ名、アプリ名・版を検証してから成果物を保存します。

成果物は `windows-update-test-0.5.0` と `windows-update-test-0.5.1` で、保持期間は14日です。それぞれに `.exe`、`.exe.blockmap`、`latest.yml` と、ソースコミット・Actions実行IDを記録した `build-info.json` が入ります。

検証済み成果物は、テスト配布用リポジトリの `v0.5.0` / `v0.5.1` Releasesに、バージョンごとに分けて配置します。`v0.5.1` を正式版・Latestとして公開することで、テスト版0.5.0から検出できます。このアプリはプレリリースを取得しないため、試験用リポジトリでもPre-releaseにはしません。Actionsは成果物保存までを行い、Release公開は別途行います。

## 最初の動作確認

1. Windowsへサインインし、GitHubからファイルを取得できることを確認します。VM内に開発環境は不要です。
2. `v0.5.0` の `NicoLiveRecorderUpdateTest-0.5.0-x64.exe` を実行します。最初は「現在のユーザーのみ」を選び、試験用アプリとしてインストールします。
3. アプリのバージョンが0.5.0、設定・保存先が上の試験用パスになっていることを確認します。設定を1つ変更し、更新後に比較できるよう値を控えます。
4. 0.5.1がダウンロード済みになった状態で、トレイから通常終了して再び起動します。バージョンは0.5.0のままであることを確認します。
5. 「再起動して更新」を押し、アプリが終了・更新・再起動することを確認します。
6. バージョンが0.5.1で、変更した設定が残っていることを確認します。試験用の `logs\app.log` に適用直前のログが残り、本番の設定・録画フォルダーを使用していないことも確認します。

試験用の録画を用意できたら、録画中の更新抑止と、更新前後の `recording-history.json` の保持も確認します。自動検知まで確認する場合は、ユーザーによるニコニコへのログインが必要です。

全ユーザー向けインストールでのUAC承認・拒否は追加試験です。拒否後にアプリが再起動しない場合は、手動起動して監視の再開を確認します。Windows版は未署名であり、初回インストールや更新がOSの保護機能に止められる場合は、その画面・結果も試験記録に残します。

## 再試験と記録

更新後に0.5.0へ戻して試す場合は、試験版だけをアンインストールし、旧版を再インストールします。ダウングレードは自動では行われません。キャッシュや設定を初期化する場合も、上表の試験用ディレクトリだけを対象にし、録画がないことを先に確認します。本番の保存先は削除しません。

記録には `build-info.json`、Windowsのバージョン・ARM/x64、インストール方式、更新前後の版、設定・履歴・ログの確認結果を含めます。ビルドの成功と、VM内での実更新の成功は分けて記録します。
