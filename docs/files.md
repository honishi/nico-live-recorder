# 出力するファイルの一覧

このアプリは、**設定・状態・ログ** と **録画** を別の場所に保存します。自動更新用のファイルは、さらに別のキャッシュへ保存します。
録画ファイルを自動で消す処理はありません。「履歴から削除」や履歴の上限超過で消えるのは履歴の項目だけで、録画ファイルは残ります。ログは退避時に `app.log.1` を上書きし、ログアウト時には購読状態とログインセッションを削除します。

## 設定・状態・ログ (userData)

| OS      | 場所                                                |
| ------- | --------------------------------------------------- |
| macOS   | `~/Library/Application Support/nico-live-recorder/` |
| Windows | `%APPDATA%\nico-live-recorder\`                     |

環境変数 `NLR_USER_DATA` で別の場所に差し替えられます (検証用)。

| ファイル                 | 内容                                                                                    | 書き方                                        |
| ------------------------ | --------------------------------------------------------------------------------------- | --------------------------------------------- |
| `settings.json`          | 設定 (保存先、録画対象、ポーリング間隔、空き容量のしきい値、画面の状態、ウィンドウ位置) | `.tmp` に書いてから置き換え                   |
| `recording-history.json` | 録画履歴 (最大 2000 件)                                                                 | 同上                                          |
| `push-subscription.json` | push の購読状態 (AutoPush の ID と endpoint、復号鍵、ニコニコへの登録状況)              | 同上                                          |
| `logs/app.log`           | ログ (info 以上。「debug を表示」が有効な間と開発時は debug も)                         | 追記。5 MB を超えたら `logs/app.log.1` へ退避 |
| `Cookies` などその他     | ログインセッションやキャッシュ。Electron 本体が作るもの                                 | Electron が管理                               |

ログアウトボタンを押すと確認ダイアログを表示します。確認すると放送開始の監視と進行中の録画を停止し、録画ファイルと履歴の書き込み完了を待ちます。開始処理中の録画も取り消します。その後、Cookie を削除する前にニコニコ側の push 登録と AutoPush のチャネルの解除を試み、`push-subscription.json` と `Cookies` のログインセッションを削除します。通信に失敗してもログアウトは完了し、次回ログインでは新しい push 購読を作成します。設定・録画履歴・録画ファイルは残ります。設定ごと初期化したいときは、アプリを終了してからこのフォルダを削除してください。

## 更新キャッシュ

`electron-updater` は macOS の `~/Library/Caches/nico-live-recorder-updater/`、Windows の `%LOCALAPPDATA%\nico-live-recorder-updater\` に更新ファイルと検証情報を保存します。`pending/` にダウンロード途中・完了済みのZIP／インストーラーなどを置きます。macOS では適用時に Squirrel が `~/Library/Caches/com.honishi.nico-live-recorder.ShipIt/` も使用します。`userData` には段階配信用の `.updaterId` も生成します。

キャッシュの整理は更新ライブラリが担当し、録画ファイルには触れません。`NLR_USER_DATA` で変更されるのは設定・状態側だけです。更新そのものを検証するときは専用の更新キャッシュ名を使って本番から分離してください。

## 録画

| OS      | 既定の保存先                             |
| ------- | ---------------------------------------- |
| macOS   | `~/Movies/NicoLiveRecorder/`             |
| Windows | `%USERPROFILE%\Videos\NicoLiveRecorder\` |

設定画面で変更できます。変更は次に開始する録画から反映され、録画中の保存先や既存ファイルは移動しません。環境変数 `NLR_OUTPUT_DIR` で既定値を差し替えられます (検証用)。`settings.json` に保存先がある場合はそちらを優先します。上記は標準的なパスで、OS 側でムービー / ビデオフォルダを移動している場合はその場所を使います。

保存先の下に `{providerId}_{配信者名}` 形式の配信者ごとのフォルダ (例: `12345678_配信者名`) を作り、1 放送につき次のファイルを置きます。ID と配信者名はファイル名に使える文字に整え、配信者名が空か取れなければ ID のみ、ID が空か取れなければ `unknown` を使います。既存のフォルダは改名しません。ファイル名は `YYYYMMDD_HHmmss_{providerId}_{programId}` です (例: `20260906_032403_12345678_lv351329587.ts`)。

日時は日本時間の放送開始日時で、端末のタイムゾーンには依存しません。開始日時が取れなければ現在日時、配信者 ID (`providerId`) が取れなければ `unknown` を使います。タイトルはファイル名に含めず、メタデータ JSON と録画履歴に残します。既存の録画ファイルは改名しません。

| ファイル              | 内容                                                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `<名前>.ts`           | 映像 + 音声 (MPEG-TS, H.264 / AAC, 取得できる最高画質、再エンコードなし)。録画が途中で止まって再開すると `<名前>_2.ts`, `_3.ts`, … と増える |
| `<名前>.comments.csv` | コメント。BOM・ヘッダー付き UTF-8 の CSV。ライブの再開では最初のファイルに追記。タイムシフトは取得ごとに新規作成                            |
| `<名前>.json`         | 番組情報と録画結果のメタデータ。映像の再開ごとに `<名前>_2.json`, `_3.json`, … を作る                                                       |

同じ放送を録り直すとき (アプリが落ちて再起動した後など) は、既存のファイルを上書きせず空いている連番を使います。

ライブ放送をアプリで録り直す場合、履歴から辿れる実在の映像ファイルとコメント CSV を引き継ぎます。CSV が残っていれば追記し、履歴や CSV がなければ新しい CSV を作ります。

### タイムシフトの再取得・部分保存

終了済み放送の手動録画では、空き連番のTS・CSV・JSONを一組確保して先頭から取得します。CSV・JSONだけが残る場合やソート用一時ファイルが残る場合も次の連番へ進み、以前のファイルへ追記・上書きしません。開始に失敗して空のままの今回のTS・CSVは終了時に整理し、診断JSONと内容のある部分ファイルは残します。

コメントは取得中にCSVへ部分保存し、終了時に投稿時刻（秒・ナノ秒）→コメント番号→取得順で安定ソートします。`<名前>.comments.csv.sorting` を新規作成して書き終えた後、その実行のCSVだけを置き換えます。停止や保存先障害では取得順の部分CSVが残ることがあります。本文に含まれる改行は維持し、vposは補正しません。

履歴は番組ID単位の1件です。`videoPaths` と容量は過去の実在動画を含む累計、`commentsPaths` は過去と今回のCSV、`commentsPath` と `commentCount` は最新CSVを指します。履歴の右クリックから実在する以前のCSVも開けます。手動停止は `completion: cancelled` として「停止」と表示し、タイムシフトの一部取得を全編完了とは表示しません。旧履歴のフィールドは移行不要で、旧JSONLもそのまま残します。

### メタデータ JSON

#### ライブ録画

録画パートの開始時に番組情報を書き、終了時にそのパートの結果で更新します。番組全体の累計は `recording-history.json` に記録します。

- `programId` / `program`: 番組 ID と取得した番組情報 (タイトル、配信者、放送開始日時など)。
- `recordedAt`: メタデータを書き込んだ時刻。
- `video`: そのパートの停止理由、録画開始・終了時刻、映像セグメント数、映像と音声の入力バイト数。TS ファイルのサイズとは一致しない場合があります。
- `comments`: そのパートで取得したコメント数、取得開始・終了時刻。追記先 CSV 全体の累計ではありません。
- `errors`: 映像・コメントの失敗理由。結果が得られなかった `video` / `comments` は省略されます。

`recordedAt` と `video` / `comments` の日時は UTC の ISO 8601 (`Z` 終端) です。ファイル名とコメント CSV の投稿時刻は日本時間です。

#### タイムシフト録画

タイムシフトのJSONには `mode: timeshift` を付け、番組情報はタイトル・配信者・開始/終了時刻だけを列挙します。視聴URLやCookieは保存しません。`recordedAt` は今回の取得開始、`updatedAt` は更新時刻です。`timeshift` に完了区分、進捗、各トラックの予定数・保存数・欠落数・HTTPステータス、コメントの取得範囲の状態・理由・件数・重複数・不正件数・ソート済みかを保存します。

最上位の `video` は停止理由と映像・音声のセグメント数、`comments` は件数のみで、ライブの日時・バイト数の構造とは異なります。動画の取得開始・終了時刻は `timeshift.video`、コメントの取得開始・終了時刻は `timeshift.comments` にUTCのISO 8601で保存します。

`timeshift.progress` には段階・保存済み/予定セグメント数・コメント状態が入ります。UIの進捗と同じ型ですが、JSONの書き込みは開始時と終了時だけで、取得中に逐次更新はしません。推定残り秒数は保存段階で解除され、通常の終了JSONには残りません。

コメントの `complete` は提供されたスナップショットの読了を意味し、番組の全コメントが揃った保証ではありません。開始直後に失敗した項目は結果がない場合があります。

`timeshift.video.playlists` には映像・音声別にタグ数、不連続境界の位置（0始まりのセグメント番号と秒数）、前後が空白か本編か、実データの連続性を確認する境界数を保存します。未対応タグで停止した場合も診断を残します。境界・未対応タグの詳細は各40件までで、URIや属性値は含めません。

`timeshift.comments.viewRequests` には、コメントの入口となるView要求ごとの所要時間（`durationMs`）と受信エントリー数（`entries`）を保存します。Viewの60秒の待機上限に達した場合は `COMMENT_VIEW_TIMEOUT`、通常のコメントファイル取得の待機上限は `COMMENT_REQUEST_TIMEOUT` として区別します。

タイムシフトの中断理由は `USER_CANCELLED`（停止）、`COMMENT_TOTAL_TIMEOUT`（コメント全体の30分上限）、`VIDEO_FAILED`（映像起因の中断）、接続エラーの固定コード、`OUTPUT_MISSING`（録画中の動画消失）を区別します。映像起因のコメント中断はJSONへ残し、画面の重複エラーは抑えます。不正な投稿時刻のコメントは除外・集計し、後続を保存して `INVALID_COMMENT_TIME` の一部失敗とします。部分動画でも `timeshift.video.ffmpegExitCode` にFFmpegの終了コードを残します。

全セグメントの取得試行とFFmpegの正常終了後の欠落は `SEGMENTS_INCOMPLETE` とし、コメントを中断せず残りの履歴を取得します。最上位の `video` は省略されますが、部分TSと `timeshift.video` の診断は残ります。`timeshift.completion` は `partial`、アプリ履歴は `failed`（画面では「中断」）となります。

### コメント CSV

列は次の14項目で固定します。

```text
at,no,content,vpos,rawUserId,hashedUserId,accountStatus,position,size,color,font,opacity,id,liveId
```

- `at` は投稿時刻の日本時間 (例: `2026-09-06T12:34:56.789+09:00`) です。端末のタイムゾーンには依存しません。
- `color` は `white` などの名前、または RGB 値を変換した `#RRGGBB` です。その他の値は取得したまま保存します。
- ヘッダーは英語の列名、データの各フィールドはダブルクオートで囲みます。内部の `"` は `""` とし、本文の改行・タブはそのまま保持します。複数行の本文も1レコードです。
- 数式に見える本文も補正せず保存します。CSV の引用符は文字列型を指定しないため、表計算ソフトの読み込み方によっては数式として扱われます。
- レコード間の改行は LF です。引用符のエスケープは RFC 4180 に倣いますが、CRLF を使う厳密な準拠形式ではありません。
- コメントの保存処理が始まれば、0件でも BOM とヘッダーを保存します。タイムシフトで接続前に失敗した場合は空の予約CSVを除去し、CSVが残らない場合があります。ライブでCSVに追記する際はBOM・ヘッダーを重複して書かず、既存ファイルの先頭が想定する BOM・ヘッダーと一致しなければ追記を中止します。コメント保存が失敗しても映像録画は続行します。
- JSONL の新規保存や形式の選択はありません。過去の `.comments.jsonl` は変換・追記・削除しません。旧形式の履歴がある番組を録り直す場合は CSV を新規に作り、取得できる過去コメントも取得します。履歴のコメント数は新しい CSV の件数になります。

## 開発用スクリプト (手動で実行したときだけ)

| スクリプト                   | 出力                                                                                                                                                        |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scripts/timeshift-probe.ts` | 既定 `.cache/timeshift-probe/` の実行別ディレクトリに `report.json` と、モードに応じて `video.ts` / `comments.jsonl`。詳細は [検証手順](timeshift-probe.md) |
| `scripts/record.ts`          | 引数の出力先 (既定 `./recordings/`) の直下に映像・コメント・メタデータ。配信者フォルダとアプリの録画履歴は作らない                                          |
| `scripts/record-comments.ts` | 既定 `./recordings/<lv番号>.comments.csv`                                                                                                                   |
| `scripts/push-listen.ts`     | 既定 `./recordings/push-state.json`                                                                                                                         |
| `scripts/e2e-screenshots.ts` | 引数の出力先 (既定 `./recordings/screenshots/`) にスクリーンショット、`electron.log`、隔離用の `userdata/` と `recordings/`                                 |
