# ハンドオフ: Nico Live Recorder 設定ウィンドウ（案 2a / タブ切替型）

## 概要
ニコニコ生放送の自動録画デスクトップアプリ（Electron、Windows / macOS、常駐 + トレイ）の設定ウィンドウ一式。
採用案は **タブ切替型（案 1a、全タブ版が 2a）**。ウィンドウを開いた直後は必ず「録画」タブで、録画中の放送と直近の録画履歴が最上部に来る。設定・ログ・履歴・対象はタブに分離。

対象タブ構成（左から）: **録画 / 対象 / 履歴 / ログ** … 右端に **設定**（日常操作と分けるため右寄せ）。

## このバンドルのファイルについて
同梱の HTML（`*.dc.html`）は **デザインの参照実装** です。見た目と構成を示すプロトタイプであり、そのまま製品コードとして取り込むものではありません。
実装対象は **React + 素の CSS（Electron のレンダラ）** で、既存コードベースの構成・命名に合わせて作り直してください。CSS は本 README の `tokens.css` を出発点にした CSS カスタムプロパティで持ち、UI ライブラリは追加しない前提です。

> **付録 A（末尾）に実装判断の追記があります。タイトルバー・最小サイズ・スクロール・失敗表示については付録 A が本文より優先します。**

## 忠実度
**ハイファイ（hifi）**。色・文字サイズ・余白・行高・角丸はすべて確定値です。ピクセル単位で再現してください。
ダミーの文言（配信者名、放送タイトル、ログ行）はサンプルであり、実装時は実データに置き換えます。

## 前提と制約
- ウィンドウ最小サイズ **760×520**（本デザインは 900×640 で作図）。それ以上に広げても崩れない列構成。
- OS のシステムフォントのみ。Web フォント・アイコンフォント・UI ライブラリは使わない。
- 装飾より状態の可読性と操作数の少なさを優先。影はウィンドウ枠のみ。
- ライト / ダークは同じ CSS 変数名で値だけ差し替える（`prefers-color-scheme` またはアプリ設定）。

- ログイン中: `● ログイン中` / `● push 接続済み` / `● 監視中 30 秒` — 円は `--success`、文字は `--text-2`。

- ログ: 未読の WARN / ERROR 件数。`--warn-weak` 地・`--warn` 文字、radius 4px。

## タブ 1: 録画（既定タブ）

### 録画中セクション
- 見出し行: 「録画中」13px/600 + 件数 12px `--text-3`（gap 8px、baseline）。見出しと本体の gap 10px。
- カード（件数ぶん縦積み、gap 8px）:
  - 背景 `--rec-weak`、枠 1px `--rec-border`、radius 8px、padding `--pad`(14px)。
  - `display:grid; grid-template-columns: minmax(0,1fr) auto; gap:14px; align-items:center`。
  - 左列（gap 6px の縦積み）:
    1. バッジ行（gap 8px）: 赤塗りピル「● 録画中」（11px/600、padding 2px 8px 2px 6px、radius 999px、白 6px 円）+ 配信者名 13px/600 + 放送 ID 11px 等幅 `--text-3`。

### 直近の録画セクション

### 未ログイン時（このタブ）
録画一覧・手動録画欄は出さず、次の 2 ブロックだけを表示。
1. カード（`--surface` 地、枠 `--border`、radius 8px、padding 26px 24px、中央揃え、gap 12px）:
   - 円 38px（`--accent-weak` 地）の中に 11px の `--accent` の円。
   - 見出し 15px/600「ログインすると自動録画がはじまります」。
   - 説明 13px/1.7 `--text-2`、max-width 430px「push 通知はログイン中のアカウントがフォローしている配信者にだけ届きます。まずログインしてください。」

2. STEP カード 3 枚（`grid-template-columns: repeat(3,1fr)`、gap 10px、`--surface-2` 地、padding 12px 14px）:

## タブ 5: 設定

3 つの群。群ラベルは 11px/600 `--text-3`（letter-spacing .04em）、群と表の gap 10px、群間 gap 18px。各群は `--surface` 地・枠 1px `--border`・radius 8px・padding `--pad`・内部 gap 12px。**保存ボタンは無く即時反映。**

1. **保存**
   - 「保存先」: `grid-template-columns: 110px minmax(0,1fr) auto`。値は 12px 等幅で 1 行省略、右に副ボタン「変更」「開く」。
   - 区切り線 1px `--border`。
   - 「ポーリング間隔」: 数値入力 64px（右寄せ、tabular-nums）+ 単位「秒」。範囲 15〜300、既定 30。
2. **検知と通知**（チェックボックス 3 つ、`align-items:flex-start`、gap 10px、チェックは `margin-top:2px`）
   - `push 通知で放送開始を検知する` — 補助文 12px/1.6 `--text-3`「切ると検知はポーリングのみになり、最大で間隔ぶん遅れます」

   - `録画の開始・終了をデスクトップ通知する`
3. **アカウント**（`grid-template-columns: minmax(0,1fr) auto`）
   - ログイン中: 「honishi としてログイン中」13px + 「push 接続済み — 最終受信 19:26:03」12px `--text-3`、右に副ボタン「ログアウト」。
   - 未ログイン: 「未ログイン」+ 「ログインすると push 通知で即時に検知できます」、右に主ボタン「ログイン」。

## 状態管理（レンダラ側の想定）

```
account:   { loggedIn, userName, pushConnected, lastPushAt }
watcher:   { polling: boolean, intervalSec }
targets:   [{ userId, name, enabled, following }]
active:    [{ liveId, userId, name, title, startedAt, bytes, comments }]   // 1 秒間隔で更新
history:   [{ liveId, name, title, startedAt, durationSec, bytes, comments, status, filePath }]
logs:      [{ at, level, text }]                                          // 直近 2000 行
ui:        { tab, showDebug, autoScroll, theme, density, historyFilter }
```

- 経過時間・サイズ・コメント数は main プロセスから 1 秒間隔でまとめて送る（行ごとの購読は作らない）。
- `history` は永続化（件数が増えるためページング前提、既定 50 件ずつ）。
- `ui` はウィンドウを閉じても保持（タブ位置と debug 表示を含む）。

## トレイ / アプリアイコン
- トレイは 16px の単色。形は円ひとつだけで状態を表す: **待機 = 輪（線 5/34 相当の太さ）／録画中 = 塗り／未ログイン = 破線の輪**。

# 付録 A: 実装前の確認事項への回答

本文と食い違う箇所は**この付録が優先**します。

## A-1. タイトルバーは OS 標準にする

フレームレス化はしない。`BrowserWindow` は macOS `titleBarStyle: 'default'`、Windows も標準フレーム。ウィンドウタイトルは `Nico Live Recorder`（バージョンは入れない）。参照実装 HTML の信号機ボタンは**作図用のダミーで実装不要**。

調整が必要なのは 3 点だけ。

1. **ヘッダからアプリ名とバージョンを外す。** OS タイトルバーと重複するため。ヘッダは「状態帯」だけになり、状態 3 つを**左寄せ**にする（本文では右寄せ）。
   - `padding: 12px 18px 0`（OS タイトルバーとの間に境界線は引かない）。
   - 状態要素は本文どおり 6px 円 + 12px テキスト、要素内 gap 6px、要素間 gap 14px。
   - 結果としてヘッダの高さは実質 28px 前後。内容領域の `padding-top` は 16px のまま。
2. **バージョンの置き場所を設定タブに移す。** 設定タブ最下部に群「情報」を追加:
   `Nico Live Recorder v0.1.0` 13px + 右に副ボタン「更新を確認」、その下に 12px `--text-3` で「ログの保存先: ~/Library/Logs/NicoLiveRecorder」。
3. **将来 `hiddenInset` にする余地だけ残す。** ヘッダ左に 78px の空きを作れば済むよう、ヘッダ左端の要素は 1 つのフレックス行にまとめておく（今は状態帯のみなので `padding-left` の変更だけで対応可）。

ウィンドウを閉じてもアプリは常駐（`close` は `hide` に読み替え、終了はトレイメニューから）。macOS では `app.dock.hide()` を使わずメニューバー常駐と Dock 非表示は設定に持たせない（当面は既定のまま）。

## A-2. 最小サイズは 760×520

本文の「760×640」は誤記。**`minWidth: 760, minHeight: 520`** が正。既定の起動サイズは 900×640、位置とサイズは保存して復元する。

520px 高でも成立させるための条件は A-6 のスクロール規則で担保する（内容領域だけが縮み、固定部は縮まない）。520px 高のとき録画タブに見えるのは「録画中カード 1 件 + 直近の録画の表 2〜3 行 + 手動録画行」。これを下限として設計してよい。

## A-3. テーマと密度

- **テーマは OS 追従のみで開始**（`prefers-color-scheme`、`tokens.css` のメディアクエリ済み）。手動切替は入れない。
- 将来手動切替を入れるときは、**設定タブに群「表示」を追加**し、位置は「検知と通知」の**下**・「アカウント」の**上**。中身はセグメント 3 択のラジオ行 `grid-template-columns: 110px minmax(0,1fr)`、ラベル「テーマ」、選択肢は **システム / ライト / ダーク**（既定「システム」）。`data-theme` 属性で `:root` に反映する（`tokens.css` はこの形で用意済み）。
- **密度はユーザー設定にしない。当面 `comfortable` 固定**（`--pad: 14px`、`--rowh: 36px`）。`data-density="compact"` は将来のための予備で、UI は用意しない。値をトークン経由で読む書き方だけ守ってほしい（直接 14px / 36px と書かない）。

## A-4. 未定義だった状態

### ボタンの disabled
`opacity` は使わず色で表す（重なった文字が薄くならないように）。`cursor: default`、`title` に理由を入れる。

| 種類 | disabled の見た目 |
| --- | --- |
| 主 | 背景 `--border-2` / 文字 `--text-3` / 枠なし |
| 副 | 背景 `--surface-2` / 文字 `--text-3` / 枠 1px `--border` |
| 破壊的 | 背景透明 / 文字 `--text-3` / 枠 1px `--border` |

入力欄が空のときの「追加」「録画開始」は disabled（現行と同じ）。停止ボタンは録画中なら常に有効。

### 処理中
**スピナーは作らない**（回転する図形を持ち込まない）。文言の差し替え + disabled で表す。ボタン幅は `min-width` を押す前の実測値に固定して、文字数でレイアウトが動かないようにする。

| 場面 | 見え方 |
| --- | --- |
| 対象の追加（ユーザー名の解決中） | ボタン「追加」→「追加中…」+ disabled。同時に**表の先頭に仮の行**を挿入: 名前列「解決中…」`--text-3`、ID 列は入力値、フォロー列は「—」、操作列は「中止」。解決できたら通常行に置き換え。 |
| ログイン | ボタン「ログイン」→「ログイン中…」+ disabled。ボタンの下（またはアカウント群の中）に 12px `--text-3`「ログインウィンドウで操作を完了してください」。ログインウィンドウを閉じられたら 3 秒で元に戻す。 |
| 手動録画の開始 | ボタン「録画開始」→「開始中…」+ disabled。成功したら入力欄を空にし、録画中カードが増える（トーストは出さない ─ カードの出現が結果表示）。 |
| 保存先の変更 | OS のダイアログ中は「変更」を disabled。 |

### 操作の失敗（3 段階に分ける）

1. **入力が原因 → 入力欄の直下にインライン表示。** 12px `--rec`、欄との gap 6px、欄の枠を `--rec` に変える。フォーカスは欄へ戻す。トーストは出さない。
   - 存在しないユーザー ID: 「このユーザー ID は見つかりませんでした」
   - 形式が不正: 「ユーザー ID か `https://www.nicovideo.jp/user/…` の形式で入力してください」
   - 既に登録済み: 「すでに録画対象です」（この場合は既存行を 1 秒間 `--accent-weak` で点灯させる）
   - 手動録画の ID 不正: 「lv から始まる ID か視聴ページの URL を入力してください」
   - 放送が終了している / 非公開: 「この放送は取得できませんでした（終了済みか非公開の可能性があります）」
2. **環境・設定が原因で解消するまで続く → ヘッダ直下の警告バナー（全タブで見える）。**
   - 見た目: 背景 `--warn-weak`、上下 1px `--border`、`padding: 10px 18px`、13px `--text`、`display:flex; align-items:center; justify-content:space-between; gap:12px`。左に 6px の `--warn` 円 + 本文、右に修復用の副ボタン。
   - 恒久的な失敗（回復操作が要る）は `--rec-weak` / `--rec` に置き換える。
   - 例: 「保存先に書き込めません」+ ボタン「保存先を変更」／「ログインが切れました」+「ログイン」／「push 通知に接続できません（ポーリングのみで監視中）」+「再接続」。
   - 同時に複数出る場合は 1 件だけ表示し、重い順（恒久的 > 一時的）に選ぶ。バナーは閉じられない（原因が消えたら自動で消える）。
3. **単発の操作の結果 → トースト（A-5）。**

### フォロー状態の「不明」
「フォロー中 / 未フォロー / 無効」に **「不明」** を追加する。中立バッジ（`--surface-2` 地・`--text-3`・1px `--border`）で文言は「不明」、`title` に「フォロー状態を確認できませんでした」。
- 判定できなかった行は**無効化しない**（録画対象としては有効なまま扱う）。
- 表の下の注記は、不明が 1 件以上あるときだけ 1 行足す: 「一部の配信者はフォロー状態を確認できませんでした。録画の対象からは外れません。」
- 再取得は表示のたびに 1 回だけ。バナーは出さない（この失敗は日常的に起きるため）。

## A-5. 未定義だった部品

### トースト
- 位置: **内容領域の右下**（ウィンドウ右下から 16px、情報バーの上）。
- 見た目: `--surface` 地、1px `--border-2`、radius 8px、影 `0 6px 20px rgba(0,0,0,.18)`、`padding: 10px 12px`、13px、`max-width: 320px`。
- 構造: 本文 + 右にリンク状のボタン（12px `--accent`、gap 12px）。
- 表示時間 **5 秒**。ホバー中は消さない。**同時に 1 件**だけ（新しいものが古いものを置き換える）。
- 文言: 削除 → 「ひとえちゃん を削除しました」/ ボタン「取り消す」。停止 → 「録画を停止しました」/ ボタン「フォルダで表示」。コピー → 「ログをコピーしました」（ボタンなし）。
- 取り消しは 5 秒間だけ有効（消えたら復元不可）。削除の確認ダイアログは出さない。

### 「詳細」リンクの遷移先
ダイアログは作らない。**ログタブへ遷移し、その放送 ID で絞り込む。**
- ログタブの操作行の下に絞り込みチップを 1 行追加: `lv351312182 で絞り込み中` + 「×」（`--surface-2` 地、1px `--border`、radius 999px、12px、padding 3px 10px）。× で解除。
- 絞り込みは行本文に該当 ID を含む行のみ表示。**debug は自動で有効化しない**（0 行になった場合だけ、本体の中央に 12px `--text-3`「この放送のログは debug 表示に含まれています」+ リンク「debug を表示」）。

### ログの「未読」の定義
**「最後にログタブを表示した時刻」より後に発生した WARN / ERROR の件数。**
- ログタブを**開いた瞬間に 0** にする（末尾まで見たかは判定しない）。
- 時刻はウィンドウを閉じても保持（`ui.logSeenAt`）。
- 表示は 99 までで、超えたら `99+`。0 のときはバッジを出さない。
- ERROR が 1 件以上あるときはバッジを `--rec-weak` / `--rec` にする（WARN のみなら warn 色）。

### push 由来の INFO を `--accent` にする基準
**当面は先頭タグ `[push]` での判定で可**（`text.startsWith('[push]')`）。
- ただし色を付けるのは「放送開始を検知した行」に相当するもののみにしたいので、`[push]` かつ `received` を含む行に限定するのが望ましい。
- 恒久対応としては logger 側に `category`（`push` / `rec` / `poll` / `comments`）を持たせ、色は category から決める形にしてほしい。文字列判定は暫定と明記しておく。

## A-6. スクロールの担い手

**原則: どのタブでも内容領域そのものは縦スクロールしない。固定部（見出し・入力行・フィルタ行・件数行）は `flex-shrink: 0`、一覧本体だけが `overflow: auto`。**（唯一の例外は設定タブ）

内容領域は `display:flex; flex-direction:column; min-height:0; overflow:hidden`。スクロールする子には必ず `min-height: 0` を付ける。

| タブ | 固定 | スクロール |
| --- | --- | --- |
| 録画 | 「録画中」見出し、「直近の録画」見出し、手動録画行（最下部） | 録画中カード列は **最大 2 件ぶんの高さ（約 236px）** を上限に内側スクロール。直近の録画の表本体は `flex:1; min-height:0` で残り高さを取り内側スクロール（ヘッダ行は sticky） |
| 対象 | 追加行、表ヘッダ、表下の注記 | 表本体 |
| 履歴 | フィルタ行、表ヘッダ、下端の件数行 +「さらに読み込む」 | 表本体（下端到達で追加読み込みしてもよいが、ボタンは残す） |
| ログ | 操作行、絞り込みチップ | 本体。自動スクロールは末尾追従。**ユーザーが上へスクロールしたら自動スクロールを自動的にオフ**にし、右下に副ボタン「最新へ」を重ねる（押すと末尾へ + 再びオン） |
| 設定 | なし | **内容領域全体をスクロール**（群が増えるため。520px 高では収まらない） |

表ヘッダ行は `position: sticky; top: 0` + 背景 `--surface-2` で固定する（本文の見た目は変えない）。

## A-7. 共有された前提への合意

- **REC レベル**: レベルではなく「録画の開始・終了」を示す印として緑（`--success`）で出す方針で問題なし。むしろ logger には `level`（debug/info/warn/error）と `category`（push/rec/poll/comments）を分けて持たせ、表示上「REC」と見せるのは category = rec の info 行、が望ましい。ログ行のレベル列は 46px 固定なので `REC` / `WARN` / `ERROR` / `INFO` はすべて収まる。
- **ユーザー名なし**: ヘッダの状態は「ログイン中」のみでよい。設定タブのアカウント群も 1 行目「ログイン中」、2 行目「push 接続済み — 最終受信 19:26:03」で確定。README 本文の「honishi として…」は読み替え。
- **履歴タブ**: 永続化と同時でよい。それまではタブ自体を出さない（4 タブ + 設定）か、空状態のみを出すかは実装側の判断で構わない。出す場合は本文の空状態をそのまま使う。
